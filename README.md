# T3Bar

T3 Code が把握している各 AI プロバイダーの使用量の上限（Session / Weekly / Monthly）を、macOS のメニューバーに表示するアプリです。T3 Code の **Usage → Limits** 画面と同じデータを、軽量な常駐メニューバー項目として手元で確認できます。

対応するプロバイダーは T3 Code が上限を報告するすべて（Claude、Codex、Cursor、Grok、OpenCode、Antigravity など）です。

## 特徴

- **プロバイダーへ直接アクセスしない**: ローカルの T3 Code サーバーから購読するのみで、各プロバイダーのログイン・API・Cookie には触れません。
- **T3 Code と同じ数字**: 直接接続とハブ経由（CLI Proxy など）の同一ログインを 1 アカウントにまとめ、複数アカウントはプランの重みで平均します。ペース判定も T3 Code と同じ規則です。
- **軽量・プッシュ駆動**: Swift + AppKit（`NSStatusItem` + `NSPopover` 内に SwiftUI）、外部依存なし、macOS 14 以降、Universal Binary、`LSUIElement`（Dock 非表示）。アイドル時の実測は RSS 約 13–16 MB / physical footprint 約 16 MB、CPU ほぼ 0%。定期ポーリングはせずプッシュを待ち、T3 Code の再起動やスリープ復帰時に自動再接続します。
- **通知は意図的に対象外**: 通知センターへのアラートは出さず、メニューバーの数値と色だけで静かに知らせます。

## インストール / ビルド

動作には macOS 14 以降、Swift 6 ツールチェーン（Xcode または Command Line Tools）、およびローカルで動作する T3 Code が必要です。

```sh
./scripts/build-app.sh            # build/T3Bar.app をビルド（Universal Binary）
./scripts/build-app.sh --install  # /Applications/T3Bar.app に配置して起動
```

アプリアイコンの生成には `rsvg-convert` を使用します。見つからない場合はアイコン生成をスキップしてビルドを続行します。

## 使い方

### メニューバー

- 残りが最も少ない上限を、ロゴ・2 本の小さなゲージ・残量（%）の順に `[ロゴ][ゲージ] 39%` のように表示します。3 要素はそれぞれ設定で切り替えられます（すべてオフでも `%` は表示）。
- ロゴとゲージはテンプレート画像として描画され、外観モードやハイライトに自動で追従します。同梱ロゴのないプロバイダーは、`アイコン` がオンのとき `%` の前にプロバイダー名を表示します。
- 2 本のゲージは表示中プロバイダーの先頭 2 ウィンドウ（通常は上が Session、下が Weekly）の残量です。
- 既定では残り **25% 以下** でオレンジ、**10% 以下** で赤になります（しきい値・オフ設定・枯渇予測による着色は `…` メニューから変更可）。
- ホバーすると表示中プロバイダーのゲージ 2 ウィンドウ（`%` の対象が別ならそれも）の残量・リセットまでの時間・枯渇予測をツールチップ表示します（複数アカウント時は `平均` 表示・予測に頭文字付き、未接続時は接続状態も表示）。
- **左クリック**: ポップオーバーを開きます。
- **右クリック**: `今すぐ再取得` / `T3 Code を開く` / `T3Bar を終了` のメニューを開きます。

### ポップオーバー

```text
  使用量の残り                         ↻   ⋯
  ● T3 Code · 16:30 更新
  ────────────────────────────────────────────

  ◆ Claude  Max
    Session  42mで枯渇                      9%
    ██░░░░│░░░░░░░░░░░░░░             ↻ 1h 40m
    ──────────────────────────────────────────
    Weekly                                 72%
    ██████████│████░░░░░░             ↻ 3d 12h

  ◆ Codex  Plus                [A1] リセット券 1
    Weekly                            平均 60%
    [A1] ████████│██████░░     82%    ↻ 3d 12h
    [A2] ██████░░│░░░░░░░░     38%     ↻ 3d 6h
         2d 7hで枯渇
```

- プロバイダーヘッダーにはカラーロゴ（上図 `◆`、Claude・Codex〔OpenAI〕・Cursor・Grok・OpenCode・Antigravity・Pi・Muse Code の 8 種同梱）とプラン名を表示します。
- **ヘッダーの補助表示**:
  - `リセット券 N`: 上限を即リセットできるクレジット（Codex）の所持数。複数アカウント時は頭文字バッジが付き、ホバーで対象アカウントと次の期限を確認できます（使用は T3 Code の Limits 画面から）。
  - `N分前` / `N時間前` / `N日前`: そのプロバイダーで最も古い取得時刻が 15 分以上前のとき表示します。
- バーの色は T3 Code の Limits 画面に合わせています（設定したしきい値以下でオレンジ／赤。既定は 25%・10%）。
- バー上の縦線（`│`）は均等ペースで今残っているはずの量です。塗りが縦線より右にあれば余裕があります。
- **枯渇予測**: ウィンドウ開始からの平均ペースでリセット前に使い切る見込みのとき、オレンジで `42mで枯渇` のように表示します。リセットまで持つ場合は無表示です。経過が約 10 分またはウィンドウの 3% 未満のとき、および既に使い切ったときは表示しません。予測が出ない状態でペースが速いとき（単一アカウント）は小さく `速め` と表示します。
- **複数アカウント**: 行の大きな数値にはプラン重み付き平均を示す `平均` が付き、各アカウントを頭文字バッジで区別します（ホバーでアカウント表示）。枯渇予測は行タイトルではなく各アカウントのバー下に表示されます。
- ヘッダーの `↻` で T3 Code サーバーに再取得を依頼します。

### ピン留めと設定

- **プロバイダーの固定**: ポップオーバー内のプロバイダーを右クリックすると、メニューバーへの固定／解除ができます。
- **`…` メニュー**:
  - **メニューバー**
    - **表示するプロバイダー**: `自動（残りが最も少ない）` または特定のプロバイダー
    - **アイコン** / **グラフ** / **残り %**: メニューバーに表示する要素のオン／オフ（すべてオフでも `%` は表示）
  - **色**
    - **少ないとき色を付ける**: メニューバー数値の着色オン／オフ（既定オン）
    - **色を付ける目安**: `残り 50%・20%` / `残り 25%・10%`（既定）/ `残り 15%・5%`。1 つ目以下でオレンジ、2 つ目以下で赤になり、メニューバーとポップオーバーの両方に適用されます
    - **枯渇しそうでも色を付ける**: 既定オフ（`少ないとき色を付ける` がオンのとき有効）。表示中プロバイダーにリセット前の枯渇予測があるとき、しきい値以上でもメニューバーの数値をオレンジにします
  - **ログイン時に起動**: `SMAppService` による自動起動のオン／オフ
  - **T3 Code を開く** / **再接続** / **T3Bar を終了**

### 接続状態とエラー表示

- **T3 Code が起動していないとき**: 起動を促す画面と `T3 Code を開く` ボタンを表示し、T3 Code が起動すると自動で接続します。
- **認証に失敗したとき**: `トークンを再発行` ボタンからトークンを作り直せます。
- **T3 Code が非互換になったとき**: 通信プロトコルが変わった場合は「未対応の T3 Code バージョン」と表示します。
- **切断中（取得済みデータがあるとき）**: 下部に警告バナーを出したうえで、最後に受け取った値を表示し続けます。

## しくみ

1. `~/.t3/userdata/server-runtime.json` からローカルの T3 Code サーバーの場所を取得します（環境変数 `T3CODE_HOME` にも対応）。
2. 初回起動時に `t3` CLI（`~/.t3/bin/t3`、なければ `/opt/homebrew/bin/t3`・`/usr/local/bin/t3`）で**読み取り専用（`orchestration:read`）**のトークンを発行します。
   ```sh
   ~/.t3/bin/t3 auth session issue --scope orchestration:read --ttl 365d --label T3Bar --token-only
   ```
   発行したトークンは `~/Library/Application Support/T3Bar/token`（パーミッション `0600`）に保存されます。サーバーに拒否された場合は自動で削除して再発行します。
3. `POST /api/auth/websocket-ticket` で WebSocket チケットを取得し、`/ws?wsTicket=…&orchestrationProtocol=2` へ接続して `subscribeServerConfig` を購読します。
4. サーバーから届く `providers[].usageLimits` と `usageLimitSources`（CLI Proxy などのハブ経由のアカウント）を集計して表示します。
5. 再取得ボタンは `server.refreshProviders` を送信し、更新結果は購読ストリーム経由で反映されます。

## 制限・注意

- **T3 Code の内部プロトコルに依存しています**: T3 Code の WebSocket プロトコルは公開 API ではないため、T3 Code のアップデートによって非互換になり、T3Bar の更新が必要になる場合があります。
- **ローカルの T3 Code が必要です**: T3Bar 単体では使用量を取得できません。
- **通知機能はありません**: 残量低下時の macOS 通知は対象外としています。

## 開発

```sh
swift test                                        # 集計・デコードロジックのテスト
swift build                                       # デバッグビルド
T3BAR_OPEN_POPOVER=1 .build/debug/T3Bar           # 起動時にポップオーバーを開いたままにする
T3BAR_DUMP_ITEM=/tmp/item.png .build/debug/T3Bar  # メニューバー描画を PNG に、ツールチップを .txt に書き出す
```
